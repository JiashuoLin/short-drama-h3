# H3 文件工作流

从用户点名的阶段进入，按授权范围推进。五文档与后期分工见 [创作文档](creator-documents.md)，
生成单位和字段见 [分段契约](segmented-contract.md)。没有内容不建空文档，不维护重复创作 JSON/JSONL、覆盖数据库或第六份接受记录。
可选原著分析的机器索引仍在 `项目开发/`，不会成为单集创作前置条件。

## 入口与依赖

1. 读取现有项目档案、用户材料和当前阶段直接输入。新套件须有用户选择；旧项目不自动改成 SEG 模式。
2. 已确认画幅写在 `short-drama.json#/format/aspect_ratio`。制作形态、H3 模式与中文视频方言由已接受生产档案提供。
   项目第一次创建时，同时确认并接受 `creator_authority.prompt_style` 全局主题；各模态从同一决策投影，细则见 [项目全局提示词风格](project-prompt-style.md)。
3. write 持有剧情和台词；assets 持有视觉事实。图片提示词和分镜是读取视觉设定的兄弟分支，不互相等待。
4. storyboard 按自然动作、对白与情绪节拍划 SEG，并在每段安排镜头。生成段通常 8–13 秒，上限 15 秒。
5. video-prompts 直接读取已定 SEG/SHOT，查看用户和项目实际媒体，在 MOTION 选择参考并生成中文六段式。
6. 需要段首/段尾图时，由 produce 直接从 `分镜.md` 对应 SEG 读取冻结正文并生产；不在 `图片提示词.md` 建重复 IMG。只有生成结果存在后才回 video-prompts 绑定。
7. 用户授权视频生成时，将一个可交接 MOTION 对应一个 SEG 的完整正文、素材及计划秒数交给外部 `minimax-h3-comfyui-video`。
8. 外部返回实际文件后记录它属于哪个 SEG/MOTION 和哪次版本；edit 读取实际媒体测量时间。需要审查时由 review 给证据并回对应 owner。

子技能路由表示读取对应职责并执行，不强制开子代理。整个套件只用文件与命令行，不启动 Dashboard、展示服务或浏览器。

## 请求范围和授权

用户要求整集时完成点名阶段的整集内容；用户要求从分镜到视频提示词时自动完成必要的上游回修再继续。
只有影响剧情或视觉方向的真实缺失选择才询问。常规字段补齐、已有图片发现、纠正结构错误不额外索要确认。
生产授权遵循用户当前和既有授权；未授权的外部生成需先把具体请求准备到可审查状态，再确认该具体范围。
创作完成、准备状态“可交接”和用户授权是三个不同事实，不把其中一个当作另外两个。

## 变更回传

| 变化 | 唯一修改方 | 复核已有下游 |
| --- | --- | --- |
| 台词、动作、VO/OS、画内文字 | write | assets、SEG/SHOT、MOTION、素材与字幕 |
| 身份、造型、空间、道具、连续性锁 | assets | IMG、段内可见状态/冻结正文、MOTION、实际图片 |
| 段拆合、镜头次序、计划时间、段首段尾 | storyboard | 可选首尾图、MOTION、视频交接和 CUT |
| 换图、图片控制范围、局部编号 | video-prompts | MOTION 定义/retention、映射与交接；不回填分镜 |
| 视频重生成 | 外部生成技能返回；produce 归属 | 实际时长、尾帧、依赖续接、CUT 与字幕 |
| 剪辑取舍与实测入出点 | edit | 成片与交付；不覆盖分镜计划时间 |

未建立的下游只说明影响，不预建空产物。分镜可保留 `参考图占位` 记录缺口，但不伪造真实 REF/PLAN；参考图若揭示与现有视觉设定冲突，先回 assets 处理事实。
连续生成只在项目已接受实际结果接力时启用；后段缺实际视频或实际尾帧就标待续接，不自动重置为独立生成。

## 明确边界

视频工作流、上传、执行预检、提交、等待、超时恢复和输出选择全部由外部 `minimax-h3-comfyui-video` 负责。
新套件不封装其 runner、不运行另一个视频 adapter，也不解决工具内部参数或工作流问题。
独立配音/TTS、时间线音乐的完整迁移，以及整集目标时长和未拍覆盖校验暂缓；保留剧本原有同轨声音表达不受影响。
